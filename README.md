# AlgoArena

Веб-платформа для небольших учебных контестов по программированию. Статический интерфейс размещается на GitHub Pages, API и SQLite работают на компьютере владельца. Базовый backend написан на Python/FastAPI; Docker не нужен.

## Что реализовано

- Аккаунты учителя и ученика, хеширование паролей PBKDF2-HMAC-SHA256, подписанные сессии.
- Учитель может создавать, просматривать, редактировать и удалять задачи; задачи содержат условие, примеры, закрытые тесты, лимит времени и памяти.
- Контесты собираются из собственных задач; код приглашения можно отправить ученикам. Длительность ученика начинается при первом открытии контеста.
- Python 3.13 и C++20 (при наличии `g++` в PATH), сравнение stdout с ожидаемым выводом, базовые вердикты, история отправок и рейтинг.
- Таблица SQLite создаётся автоматически, включены внешние ключи и WAL.
- Автосохранение исходного кода в браузере; GitHub Actions публикует `frontend/` на GitHub Pages и внедряет URL backend из переменной репозитория `API_BASE_URL`.
- Интерфейс разделён на вкладки «Контесты», «Задачи контеста», «Отправки и рейтинг» и «Мои задачи». Окно входа скрывается после входа; настройки API в интерфейсе нет.
- API-документация доступна на `/docs`.

## Важное ограничение безопасности (прочитай до запуска)

**Без Docker или другой полноценной изоляции нельзя безопасно исполнять произвольный код учеников на компьютере, где хранятся личные файлы.** Python и C++ — полноценные языки ОС: пользовательская программа может читать/изменять доступные файлы, запускать процессы и пытаться обращаться к сети. Таймаут процесса не является песочницей и не даёт надёжных лимитов памяти.

В этой версии runner работает без Docker ради простого локального запуска. Используй его только в доверенной группе, лучше на отдельном Windows-пользователе/компьютере без личных данных. Не публикуй такой API через Cloudflare Tunnel/проброс портов для незнакомых пользователей. Для публичного контеста подключи изолированный удалённый judge (например, Judge0) либо вернись к Docker/Windows Sandbox/виртуальной машине и проведи аудит безопасности. Runner можно отключить, установив `ALLOW_UNSAFE_RUNNER=0`.

## Windows: быстрый запуск без Docker

1. Установи **Python 3.11+** с сайта python.org и включи опцию Add Python to PATH.
2. Для C++ установи компилятор с поддержкой C++20, например [MSYS2 MinGW-w64](https://www.msys2.org/), затем добавь каталог `.../mingw64/bin` в PATH. Python-задачи будут работать и без `g++`, но C++ тогда будет недоступен.
3. Запусти `backend/start.bat` (или PowerShell-скрипт `backend/start-local.ps1`). Скрипт создаст `.venv`, установит зависимости и запустит API только на `127.0.0.1:8000`. При запуске можно указать разрешённые origin через запятую; для локальной разработки нажми Enter.
4. При первом запуске задай секрет регистрации учителя. Его нужно сообщить только тем, кому разрешено создавать учительские аккаунты. Владелец сервера также должен задать стабильные `TOKEN_SECRET` и `TEACHER_INVITE`, если хочет сохранять конфигурацию между перезапусками.
5. Скрипт откроет сайт на `http://127.0.0.1:5500` и API на `http://127.0.0.1:8000`. Проверь статус API и создай учительский аккаунт. Не открывай HTML двойным кликом: запуск через локальный HTTP-сервер нужен для CORS.
6. Учитель создаёт задачу, затем контест. Ученики регистрируются как ученики, вводят код контеста и отправляют решения.

### Рекомендуемый стабильный запуск из PowerShell

В каталоге `backend` выполни:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:TOKEN_SECRET = [guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
$env:TEACHER_INVITE = Read-Host 'Секретный код регистрации учителя'
$env:ALLOW_UNSAFE_RUNNER = '1' # только доверенный локальный класс
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Если каждый раз генерировать новый `TOKEN_SECRET`, ранее выданные сессии перестанут работать, но аккаунты и задачи в SQLite сохранятся. Для постоянной установки сохрани случайный `TOKEN_SECRET` в пользовательских переменных среды. Не используй примерный/публичный секрет в интернете.

## Проверка C++ и Python

- Python: команда `python -I -B main.py`; используй Python 3.13 (или задай `CONTEST_PYTHON` полным путём к нужному интерпретатору).
- C++: `g++ -std=c++20 -O2 -pipe`; настрой `CONTEST_CPP`, если `g++` не находится через PATH.
- Для каждой задачи сервер запускает код отдельно для каждого теста. Ограничение времени применяется к каждому запуску; компиляция ограничена 20 секундами.
- Поле лимита памяти пока хранится в задаче для совместимости интерфейса, но без sandbox/OS job limits оно **не является жёстким лимитом памяти**.
- Сравнение вывода игнорирует пробелы и переводы строк по краям, но сохраняет различия внутри вывода.

## Публикация сайта на GitHub Pages и настройка API

GitHub Pages хостит только статические файлы. Он не запускает FastAPI, SQLite или компилятор. Поэтому для реальных аккаунтов, общих контестов и отправок нужен работающий backend с постоянным доступным HTTPS-адресом. Сайт больше не просит пользователей вводить IP: URL API задаётся при сборке через GitHub Actions.

1. Создай GitHub-репозиторий и загрузи содержимое `contest-kit` в корень ветки `main`.
2. Открой **Settings → Pages** и выбери **GitHub Actions**.
3. Создай репозиторную переменную **Settings → Secrets and variables → Actions → Variables → New repository variable**: имя `API_BASE_URL`, значение — публичный HTTPS URL backend без завершающего слэша, например `https://api.example.com`.
4. Workflow `.github/workflows/pages.yml` создаст `frontend/config.js` с этим адресом и развернёт фронтенд. После изменения переменной запусти workflow вручную или отправь новый commit.
5. На backend задай `CORS_ORIGINS` со значением origin опубликованного сайта, например `https://USERNAME.github.io` (без пути `/имя-репозитория`), при необходимости добавив `http://localhost:5500` для локальной разработки.
6. Убедись, что backend URL доступен снаружи по HTTPS и endpoint `/api/health` отвечает. Ученики открывают GitHub Pages, а все их запросы направляются на один backend и одну SQLite базу.

**Важно:** если backend остаётся на твоём компьютере, он должен быть включён, а публичный HTTPS-туннель — работать. Сам по себе GitHub Pages не может автоматически подключиться к твоему компьютеру и не может заменить backend. Не используй `127.0.0.1` в `API_BASE_URL` для опубликованного сайта: у каждого ученика этот адрес означает его собственное устройство.

**Безопасность:** текущий runner запускает произвольный код без полноценной песочницы. Не публикуй его в открытый интернет для незнакомых пользователей, даже если включён CORS и настроена авторизация. Для публичного контеста сначала перенеси исполнение в изолированный сервис/виртуальную машину и проведи аудит безопасности.

## Данные и резервная копия

- База: `backend/contest.db` (создаётся при старте). Секрет подписи сессий при запуске через BAT хранится в `backend/.token_secret`.
- Для резервной копии останови сервер и скопируй `contest.db` в защищённое место.
- Не загружай базу, токены, `.venv` и личные данные в GitHub. В `.gitignore` уже добавлены база и виртуальное окружение.
- При удалении контеста удаляются связанные отправки. Задачу, которая включена в существующий контест, удалить нельзя — сначала удали соответствующий контест.

## Структура

```text
contest-kit/
  frontend/index.html
  frontend/config.js  # локальный URL берётся из localhost; CI подставляет API_BASE_URL
  backend/main.py
  backend/requirements.txt
  backend/start.bat
  backend/start-local.ps1
  .github/workflows/pages.yml
```
